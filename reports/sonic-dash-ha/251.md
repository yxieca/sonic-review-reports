## R1 — Restore the existing recorder behavior in release artifacts

**Preserve release-mode recorder events.** Following the [existing tracing concern](https://github.com/sonic-net/sonic-dash-ha/pull/251#discussion_r4713878764), the new [shared Rust dependency selection](https://github.com/sonic-net/sonic-dash-ha/blob/b69043a63d339e8f81b5bc9eb57f2f16612deaf1/MODULE.bazel#L19-L31) enables `max_level_debug` and `release_max_level_info`. In a release build, tracing's static maximum becomes INFO before runtime filters run. Existing [actor receive/send producers](https://github.com/sonic-net/sonic-dash-ha/blob/b69043a63d339e8f81b5bc9eb57f2f16612deaf1/crates/swbus-actor/src/driver.rs#L76-L106) emit `debug!(target: "hamgrd-recorder", ...)`, and [hamgrd's logger setup](https://github.com/sonic-net/sonic-dash-ha/blob/b69043a63d339e8f81b5bc9eb57f2f16612deaf1/crates/hamgrd/src/main.rs#L49-L63) installs an [independent TRACE-capable file layer](https://github.com/sonic-net/sonic-dash-ha/blob/b69043a63d339e8f81b5bc9eb57f2f16612deaf1/crates/sonic-common/src/log.rs#L209-L253). The new release artifact therefore loses those DEBUG recorder events even when runtime logging requests them. `force_debug_build` retains symbols but does not change compilation mode, so it does not restore the events; tracing's ordinary `log` fallback is also disabled once the dispatcher is installed. Please select a feature profile without the incompatible static caps and add a release-mode recorder-emission regression case. This is source-grounded; no native logging, build or HA test was executed by this review.

**Introduced versus inherited:** The actor event producers and independent recorder are present at BASE. The new Bazel graph selects shared tracing static-cap features absent from the workspace's declared tracing profile. This additional build path creates the loss; it is not a claim that the unchanged Cargo/Debian artifact was newly modified.

**Complete source chain:** shared tracing features → static INFO selection when debug assertions are off → event macro guard → existing actor DEBUG event → hamgrd's independent recorder. The selected tracing source explains that disabled events may emit through the ordinary `log` bridge before a dispatcher is installed; its actual fallback branch does not restore the recorder after HA installs its tracing registry. Symbol retention changes strip/debug flags, not the release compilation mode.

**Small correction:** Preserve the existing consumer logging behavior by removing the incompatible static caps from its selected feature profile, and verify an actual release-mode recorder event in a narrowly scoped regression test. This review inspected source, not a compiler output or live log file. The target thread is still open without an author reply.

## Q1 — State and reconcile the producer's dependency contract

**Clarify the canonical dependency contract.** The [existing dependency-selection question](https://github.com/sonic-net/sonic-dash-ha/pull/251#discussion_r4713886917) remains unanswered. The new Bazel graph consumes the shared owner's lock rather than this workspace's `Cargo.lock`: examples are file-rotate **0.7.6 versus 0.8.0**, signal-hook **0.3.17 versus 0.4.6**, Tokio **1.38.2 versus 1.51.6**, and a different Common source revision. Could the selected versions/features be aligned with the canonical workspace requirements, or could the deliberate differences and their supported API/lifecycle acceptance be documented and reviewed explicitly? These are material producer selections, but version inequality alone is not evidence of a second runtime defect. The inspected file-rotate caller passes `None`, which is accepted by both constructor variants, and the scoped blocking-task adapter is present in both inspected Common revisions. Keep the release-logging correction above separate from that broader contract question.

**Introduced versus inherited:** The workspace manifest/lock is unchanged. The alternative Bazel path adds a shared lock/source selection that does not satisfy every workspace version expectation verbatim. That warrants explicit reconciliation of the declared producer contract; it does not prove universal wire/API/ABI incompatibility.

**Evidence and limits:** Source inspection covered the selected and canonical Common counterpart, the used async/FFI/test interfaces, and selected logging/rotation/code-generation implementations. The transmuted scoped blocking-task helper and its cancellation caveat are present in both Common source revisions, so no newly introduced lifetime defect was established merely from changing the source owner. File-rotate's constructor changes from optional Unix mode to optional OpenOptions, but this caller's `None` uses compatible default opening behavior. No actual HA signal-hook caller was established from an unused declared dependency alone.

**Small next step:** Either align the shared selection with the canonical workspace contract or explicitly review/document the deliberate differences and their acceptance. Fix R1 independently; do not require a complete transitive-universe or hardware test campaign to discuss the source-level selection.
