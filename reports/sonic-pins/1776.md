It is not a CMake migration or a version-only edit.

The current native full-suite workflow executed **236 test targets**, and the production-runtime job executed its one package test. Those are inspected external results on a merge tree matching this HEAD, not reviewer-executed tests or proof that manual freshness goldens ran.

## Source conclusions

### Dependency and generated-header migration

[MODULE](https://github.com/sonic-net/sonic-pins/blob/a19f75089872524643c4a58eecbfe074458cd1fc/MODULE.bazel) replaces the old WORKSPACE wiring with explicit SONiC/BCR modules, native tools and root overrides. Public gNMI/gNOI generators add their `github.com/openconfig/...` import prefixes; P4Runtime instead strips `/proto`, retaining `p4/v1` and `p4/config/v1` header paths. Mock generation and caller BUILD dependencies were inspected, not inferred from version names.

All 98 include-only files have identical non-include lines at the exact BASE/HEAD. Their 27 mapping classes include namespace/header corrections and a few explicit includes for already-used APIs. The changed dependency/compiler graph can still affect behavior; unchanged C++ body text is not a guarantee of binary or ABI equivalence.

The P4 constraint/dependency API changes, shared Common/libnl providers, protobuf rules and new native preprocessing action were followed through their actual source boundaries. [SAI preprocessing](https://github.com/sonic-net/sonic-pins/blob/a19f75089872524643c4a58eecbfe074458cd1fc/sai_p4/instantiations/google/preprocess.bzl) selects the registered C compiler and declares its tools/P4 headers rather than depending on an ambient preprocessor. Its eight source test instantiations check standard/BMv2 file accessibility; this is distinct from the four P4Info freshness comparisons and does not itself prove semantic equality of every generated payload.

### Session helpers are moved, not removed

[Public session wrapper/core targets](https://github.com/sonic-net/sonic-pins/blob/a19f75089872524643c4a58eecbfe074458cd1fc/p4_infra/p4_runtime/BUILD.bazel#L25-L78) preserve both ThinKit factory definitions in `p4_runtime_session_thinkit.cc` and their header declarations. The public wrapper links that file and the core; production clients can use the lean core without a ThinKit dependency.

An apparent method removal found in a partial `.cc` window was withdrawn after reading the replacement file, header and caller target. No dangling method/caller break was established. This is dependency separation, not proof that client protocol/shutdown behavior or device state was executed here.

### Source-owned production runtime

[Production declarations](https://github.com/sonic-net/sonic-pins/blob/a19f75089872524643c4a58eecbfe074458cd1fc/p4rt_app/BUILD.bazel) package six programs under `usr/local/bin`, with root-owned executable modes, canonical timestamps, paired detached symbols and Debian-derived dependency metadata. Legacy DEB targets remain manual; selected graph audits do not imply that all binary package inputs or arbitrary effects are absent.

The runtime test inspects archive inventories, ELF hardening, dynamic dependencies, absent runtime debug sections/RPATH, matching build IDs, positive/negative GDB lookup, CLI flags and `--only_check_args`. The checker follows source-built Common/libnl inputs and rejects visible embedded netlink exports. These are meaningful acceptance predicates, but no archive, ELF, GDB or CLI was executed by this review.

### Route-measurement conversion preserves failure reporting

[The companion tool](https://github.com/sonic-net/sonic-pins/blob/a19f75089872524643c4a58eecbfe074458cd1fc/p4rt_app/scripts/p4rt_route_measurement_test.cc) replaces its GoogleTest shell with status-returning setup/measurement/teardown and a standard main. Measurement or teardown errors return nonzero; test-only matcher dependencies are removed from the production path. The helper remains capable of real P4Runtime changes when invoked—help/argument checks do not qualify those operations.

## Nonblocking follow-up

### N1 — Retain a final cleanup attempt after setup failure

[Current main](https://github.com/sonic-net/sonic-pins/blob/a19f75089872524643c4a58eecbfe074458cd1fc/p4rt_app/scripts/p4rt_route_measurement_test.cc#L1950-L1975) returns immediately when `SetUp` reports an error. The former GoogleTest fixture finalized with `TearDown` even after failed setup; the declared old framework source confirms that contract.

**Condition/consequence:** With `--cleanup=true` and a session already created, failure during setup can now skip the last best-effort `ClearEntities` attempt. This is loss of a cleanup attempt, not proof that a new device mutation, persistent leak or outage occurred. Failures after measurement still run teardown.

**Optional correction:** Route failure exits through finalization when a session exists, or use a scoped finalizer, retaining the original failure status and reporting cleanup errors separately. This can follow separately; no fault injection, device access or C++ execution was performed.

### Q2 — Installed CLI tests are not isolated image acceptance

`runtime_package_test.py::stage_runtime_lib_dir` collects eligible runfiles libraries, uses the first eligible basename and excludes libc/loader candidates. `main` retains the inherited `LD_LIBRARY_PATH` after the staged directory. Successful CLI loading therefore establishes operation with those runfiles and system libraries, not independent installation of a complete target dependency closure.

The receipt does not record every resolved library path/hash or `ldd` output. If stronger provider proof is required, retain a curated library-resolution receipt or qualify a separate image consumer. This is a validation scope/optional evidence improvement, not a demonstrated failure of the current package.

The pinned bootstrap configuration/manifest is separate from catalog selection: `.bazelrc` resolves registry `main` plus BCR. Hash-checking files fetched from commit `55c38af` does not freeze all registry responses to that commit. Declared source integrity and recorded resolution remain meaningful, but an immutable whole-catalog claim is not made.
