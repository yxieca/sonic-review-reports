## Q3 — Separate shared runtime/binding adaptations from Bazel enablement

This PR is not strictly Bazel-only. Two shared source changes affect existing build-path consumers:

- `common/redisapi.h::loadLuaScript()` adds `SWSS_COMMON_LUA_DIR` and path validation. Unset/empty retains legacy loading; nonempty changes shared runtime behavior. The override supports staged runtime Lua access, not C++ compilation itself.
- `pyext/swsscommon.i` adapts static string-constant wrapping for Python and Go. With selected SWIG 4.3, automatic mutable-pointer wrappers conflict with const-pointer C++ declarations. The source documents this compilation problem; this review did not rebuild a reverted version. These directives also affect bindings generated outside Bazel.

The request is to move these changes into a separately reviewed prerequisite PR, retaining their dependency where necessary—not remove a required compilation fix. `sonic-db-cli` has test/build wiring, but is not the location of these two shared changes. Ask the author to identify the minimal prerequisite and its Make/Bazel compatibility validation.
