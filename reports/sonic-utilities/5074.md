## R1 — new resolver rejects previously readable ganged entries

**Exact condition.** Static topology contains two valid interfaces with physical index tuples `(1,)` and `(2,)`, each referring to its own OE/ELS; the active PORT configuration contains one differently named logical ganged port with index `(1, 2)`. Static interface parsing can use their own explicit index/lanes when the static names are absent from active PORT. `load_cpo_object_map` builds physical CPO entries for both. `get_port_cpo_entries` then returns two member records for the active ganged logical port. This is not an invalid selector, absent CPO or missing device API.

The base `show_interface_dom` reads those two CPOs without resolving a single static interface. The head passes the **same logical name** for both to `resolve_interface`. Because that name is not an exact static key, the resolver matches by physical-index intersection, finds both static interfaces and raises `CpoMappingError("Unable to resolve ... to one CPO interface")`. The outer handler turns that into a fatal ClickException before the final output. This is a static source trace, not an executed simulation or observed deployed outage.

**Immutable source evidence:** [physical-entry construction and loader](https://github.com/sonic-net/sonic-utilities/blob/5240b3d4505534b82848a7b9c9e073be25663e4a/cpoutil/main.py#L150-L262), [new unconditional mapping and cache](https://github.com/sonic-net/sonic-utilities/blob/5240b3d4505534b82848a7b9c9e073be25663e4a/cpoutil/main.py#L1144-L1215), [static parsing and single-match resolver](https://github.com/sonic-net/sonic-utilities/blob/5240b3d4505534b82848a7b9c9e073be25663e4a/cpoutil/mapping.py#L170-L265), [base DOM](https://github.com/sonic-net/sonic-utilities/blob/31df09e10cd153ab0f3a32b939fc595e05dc1525/cpoutil/main.py#L1123-L1198).

## Q1 — physical-member identity, not merely different Python objects

The cache key is a topology device/bank, intentionally **not** Python endpoint identity. Different objects can legitimately expose the same device/bank, so different object addresses or fabricated different temperatures alone do not demonstrate a defect. Conversely `get_port_cpo_entries` supplies a physical member, but the new loop discards its index and resolves only the logical name. Where a logical name has an exact static match, every member gets that same key. Correctness then relies on the platform/topology contract that all such members really expose the same selected bank's aggregate data.

Before claiming a specific hardware data-duplication defect, inspect the selected platform factory and effective topology together. None was executed or assumed deployed here. The safe source correction is to retain per-member reads where that identity is ambiguous; no new capability registry, device probe or hardware preflight is demanded. The author-reported NVIDIA single-bank sharing remains an intended supported optimization, not an invented blocker.
