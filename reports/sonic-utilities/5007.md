## R1 — availability failure escapes the per-target boundary

**Condition and consequence.** The topology declares `els0` and `els1`, while the CPO table has only `els1`. `CpoMapping.resolve_resource_ids(None, EXTERNAL_LASER_SOURCE)` returns both declared IDs. `get_resource_cpo_objects` raises immediately on `els0`; it never returns the list to `_run_firmware_operation` or `_show_firmware_version`. The healthy `els1` hook is not called and its version is not emitted. Selecting `els1` directly succeeds because its single lookup exists.

**Immutable evidence:** [resolver](https://github.com/sonic-net/sonic-utilities/blob/8fb199d6da3e909fea0cf2261ef4afd23f8e373a/cpoutil/main.py#L264-L286), [firmware target wrapper and loop](https://github.com/sonic-net/sonic-utilities/blob/8fb199d6da3e909fea0cf2261ef4afd23f8e373a/cpoutil/main.py#L2298-L2381), [fwversion resolution](https://github.com/sonic-net/sonic-utilities/blob/8fb199d6da3e909fea0cf2261ef4afd23f8e373a/cpoutil/main.py#L2577-L2603), [declared resource selection](https://github.com/sonic-net/sonic-utilities/blob/8fb199d6da3e909fea0cf2261ef4afd23f8e373a/cpoutil/mapping.py#L222-L237). `load_cpo_object_map` explicitly skips interfaces whose `get_cpo` returns None while retaining healthy interfaces; thus the missing-object state is supported by the actual initialization code, not just a fabricated malformed hook.

**Baseline classification.** The base resolver already raises on a missing CPO. Existing generic show/control semantics are not claimed to regress. The firmware and fwversion entry paths are new, and their new per-target contract is not met. [HLD 7.9](https://github.com/sonic-net/SONiC/blob/68ef12a9a83929905bc5a991d9d7c2dedb811941/doc/cpo-util/cpo-util-hld.md#L529-L545) distinguishes invalid selection from unavailable per-target objects.

**Smallest correction.** Validate the selector and enumerate declared IDs first; resolve each CPO/endpoint inside the firmware-specific per-target try block. Preserve fatal invalid-index behavior and existing unrelated callers. Record unavailable target labels, continue healthy targets, and retain a nonzero aggregate result. Add tests where one declared CPO is missing, not only where a present CPO has a missing endpoint or a hook raises.

**Discussion:** [existing human thread](https://github.com/sonic-net/sonic-utilities/pull/5007#discussion_r4679062681). No author reply or resolution was present in the retrieved complete thread. Do not post a duplicate finding.

## N1 — empty info accepted

The new [dict check](https://github.com/sonic-net/sonic-utilities/blob/8fb199d6da3e909fea0cf2261ef4afd23f8e373a/cpoutil/main.py#L2599-L2604) accepts `{}`; `_add_firmware_banks({})` returns `{}` and the target is counted successful. Preserve valid EEPROM-only dictionaries (including explicit N/A versions), but reject an empty dict as no data. The pinned tests reject None/string, not `{}`. This is a new robustness gap, not evidence that normal hardware returns empty data. [Existing thread](https://github.com/sonic-net/sonic-utilities/pull/5007#discussion_r4679062701); nonblocking in this assessment.

## Q1 — hook completion versus verified new image

The CLI delegates the whole upgrade to the endpoint generator and prints OK on successful exhaustion. That is compatible with the stated hook contract; imposing a new CLI-specific lower-level CDB sequence would break platform abstraction. Independently inspected platform-common #790 HEAD `7b1dccafb8498ee3c30b200e623219d364859aad` implements download, run, five-second wait, API refresh and commit in `CdbFirmwareMixin`, but does not explicitly compare the running image before committing. The pinned utilities `sfputil.is_fw_switch_done` instead polls firmware status for a valid running uncommitted image before its commit.

[Existing question](https://github.com/sonic-net/sonic-utilities/pull/5007#discussion_r4682235520) therefore remains useful integration qualification. No physical rollback, failed image activation or selected deployed package version was observed. This is **not** promoted to a demonstrated blocker in utilities #5007, and the independently pinned #790 source is not assumed installed with this utilities head. Firmware validation and locking belong to the selected platform implementation; the HLD explicitly delegates image validation and concurrency. Deployment acceptance requires its own version/pin and hardware evidence.

## N2 — partial progress obscured by unsupported wording

A generator can yield bytes and later raise NotImplementedError. The [transfer exception handler](https://github.com/sonic-net/sonic-utilities/blob/8fb199d6da3e909fea0cf2261ef4afd23f8e373a/cpoutil/main.py#L2312-L2337) reports only 'not implemented for this platform', although bytes were written. A late failure should retain operation/progress context. The command still fails, closes the generator and continues later targets, so this is diagnostic, not a false successful upgrade. [Existing thread](https://github.com/sonic-net/sonic-utilities/pull/5007#discussion_r4682235545). A byte-count rule alone cannot distinguish all phase boundaries; do not imply it proves which firmware phase completed.
