## R1 — Restore non-ASAN fortification parity

**Restore the existing non-ASAN fortification policy in the Bazel build.** The exact baseline [Debian recipe](https://github.com/sonic-net/sonic-sairedis/blob/22550fa427562f31d3bde5c66e622a437a5f6496/debian/rules#L19-L24) explicitly adds `-U_FORTIFY_SOURCE -D_FORTIFY_SOURCE=3` for non-ASAN compilation. Thus the supported default native Trixie AMD64/ARM64, VS, Python-3, non-ASAN path loses that existing hardening policy. Please carry the non-ASAN undefine/redefine into the relevant compilation paths after the toolchain definition, while retaining the existing ASAN exception. This is a source-defined hardening-policy discrepancy, not a reproduced exploit or evidence that other hardening is absent.
