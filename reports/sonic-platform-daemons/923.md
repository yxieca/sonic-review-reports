- [judyjoseph discussion 4635112636](https://github.com/sonic-net/sonic-platform-daemons/pull/923#discussion_r4635112636): why was this code removed for graceful restart feature ?
- [william8545 discussion 4635194095](https://github.com/sonic-net/sonic-platform-daemons/pull/923#discussion_r4635194095): The check is still there. It is now `_guard_should_skip()`, and `_dispatch()` calls it for each request.

The condition for a power-off changed. The old check skipped a power-off when the host was `OFFLINE`, or when the recorded state was `POWERING_OFF` or `GRACEFUL_SHUTTING_DOWN`. The new check skips a power-off only when the host is `OFFLINE` and the recorded state is `POWERED_OFF`.

In this feature, a critical power-off can preempt a graceful shutdown, and the `GRACEFUL_SHUTTING_DOWN` label stays. The old check would then skip the power-off while the host is on.
- [judyjoseph discussion 4635132744](https://github.com/sonic-net/sonic-platform-daemons/pull/923#discussion_r4635132744): I have a similar question here too ? We actually need this check

- [william8545 discussion 4635198859](https://github.com/sonic-net/sonic-platform-daemons/pull/923#discussion_r4635198859): The two checks are still there.

- Leak check: `_enqueue_startup_power_on()` calls `is_power_on_blocked()`.
- Rack Manager check: `_dispatch()` calls `_rm_removal_recorded()`.

The startup power-on is now a request in the queue, so that a power-off can preempt it.
