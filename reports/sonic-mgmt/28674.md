## Important nonblocking questions / improvements

1. **Prove every intended sender/QP participated before accepting an X-QP scenario.**  
   `test_rocev2_hashing_lb.py:218–245`; helper `is_traffic_running`, `run_rocev2_step`, `assert_queries`. The full test never reconciles expected active QP names/count against returned metrics or requires valid positive traffic for each intended sender. Aggregate port activity is not that evidence. Please retain a negative control where an eight-QP scenario returns only one active QP with valid positive counters and zero delta, while other expected QPs are absent; verify the actual acceptance path rejects it. Receive-only stacks must be excluded from active-sender requirements. **Not a reproduced false PASS:** pandas query/NA execution was unavailable, so possible zero/invalid-counter behavior remains explicitly unverified.

2. **Set native stagger flags explicitly for both staggered and nonstaggered cases.**  
   `test_rocev2_hashing_lb.py:85–96,181–193,250–252`. The API fixture is **module-scoped**; flags are only assigned `True`, while nonstagger cases supply no hook. The reference backend reconfigures objects and only calls `NewConfig` for an empty config; no explicit stagger reset was found in the reached source. Assign both properties from the current scenario and verify the transition `2pair_1qp_stagger → 2pair_Xqp`. **No hardware state-leak claim is asserted:** installed backend/server reset behavior and physical timing were not observed. The session is removed at module teardown, so a cross-module leak is not claimed.

3. **Own any DUT setup changes locally rather than depend on health recovery.**  
   New test `119,185,250–252`; `snappi_fixtures.py:1286–1355,1446–1526,1810–1852`. Base-config acquisition can add interface addresses on its fallback path, before topology skip checks, while the test's finalizer only stops the tester. A fixture-owned setup/release would be cleaner. **Nonblocking on the stated preconfigured fabric:** root `core_dump_and_config_check` does detect and restore changes by whole-DUT reload, and the reference layout can use existing L3 configuration. “Permanent leak/no restoration” would be false.
