## Summary
The two fixture changes match issue #28863: wait for Supervisor to report bmcctld **RUNNING** on BMC devices, fail on timeout rather than silently skip, and skip non-BMC devices before polling or collecting data.

`TestBmcctldDaemon.setup` (`test_bmcctld.py:66–79`) retains the function-level gate for each of five class tests. `bmcctld_data_before_restart` (`:611–620`) supplies the module-level gate for all four standalone lifecycle tests, before STATE_DB collection. The existing status helper and `wait_until` retry normal callback/parser failures; the new assertions make persistent unavailability fail setup. The gate does not start or enable the daemon, so it does not conceal initial startup failure by repairing it.

Removing the disabled-daemon skip is deliberate fail-closed behavior, not a demonstrated compatibility regression. The removed helper checked membership in a filtered Supervisor process list, so it could also skip a daemon that had not appeared yet.

## Non-blocking notes
### Grounded evidence / process note
The PR requests and marks testing on **202608**, but its evidence is only “Tests dont skip, with this change.” Add the image version and branch-specific run/log results, preferably covering delayed startup, persistent-unavailable timeout, and non-BMC exclusion. The existing [BuildBot comment](https://github.com/sonic-net/sonic-mgmt/pull/28864#issuecomment-6474117625) already requests the backport evidence; do not post a duplicate finding.

### Scope limits, not requested code fixes
- **RUNNING is process readiness, not full application initialization.** No production-daemon timing evidence establishes a newly introduced subscription/DB race. Base class setup already accepted RUNNING, and the old lifecycle fixture collected data even earlier. The returned lifecycle snapshot is not consumed by the four existing test bodies.
- **800 seconds is a polling budget, not a hard remote-call cancellation deadline.** The shared helper uses wall-clock `time.time()`, not a monotonic clock. Healthy processes pass immediately; persistent failure can repeat the budget across class tests. These limitations do not justify removing per-test health checks or restoring silent skips.

### Best-practice only
The two identical polling/assertion blocks could share constants or a small helper. This is optional maintainability work, not a correctness nit and not necessary for approval.
