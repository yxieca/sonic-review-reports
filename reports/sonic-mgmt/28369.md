## R1 — Keep runtime recovery owned by the module-scoped checked reload

**Kind:** blocking integration concern. **Priority:** P2. **Status:** open. **Introduced versus inherited:** the raw operation is introduced by this PR; the module caller is later upstream scope, and the report-only exception handler is inherited.

Immutable source:
- [PR insertion, helpers.py:144–152](https://github.com/sonic-net/sonic-mgmt/blob/f445237b36b18c0db54d4cd669399f3dbcb4281d/tests/gnmi_benchmark/helpers.py#L144-L152).
- [Cutoff route cleanup and file restoration](https://github.com/sonic-net/sonic-mgmt/blob/42205428fbe07ed1d12ea4e8b0eb654b78891726/tests/gnmi_benchmark/helpers.py#L61-L65), [_restore_config:118–125](https://github.com/sonic-net/sonic-mgmt/blob/42205428fbe07ed1d12ea4e8b0eb654b78891726/tests/gnmi_benchmark/helpers.py#L118-L125).
- [Module recovery:67–83 and entrypoint:102–130](https://github.com/sonic-net/sonic-mgmt/blob/42205428fbe07ed1d12ea4e8b0eb654b78891726/tests/gnmi_benchmark/test_gnmi_benchmark.py#L67-L130).
- [Common checked reload](https://github.com/sonic-net/sonic-mgmt/blob/42205428fbe07ed1d12ea4e8b0eb654b78891726/tests/common/config_reload.py#L364-L590).

The module finalizer first calls `_restore_config(host, backup)` and then `config_reload(..., safe_reload=True, check_intf_up_ports=True, wait_for_bgp=True)`. With the insertion, a nonzero raw reload makes `_restore_config` raise even after successful file copy/comparison. The following checked recovery is not reached. The finalizer's `finally` enters the block but does not guarantee each subsequent statement runs. The backup is retained by the shell's `&&` chain.

**This module failure propagates as a teardown error; it is not swallowed by the test body.** The defect is loss of the checked recovery attempt, not an assertion that the entire module silently passes. The checked helper can select force reload when supported and provides database/service/process, interface, BGP and default YANG checks. Its caller keyword is exactly compatible; no signature mismatch exists.

At the separate per-case call site, resource ExitStack removal precedes restoration, and restoration still runs if removal raises. A new raw-reload exception passes through the runner into the inherited report-only test handler; that case can have a successful call phase without a generated report. Later TLS/module cleanup may detect or repair the state, so persistent unrecovered state is not inevitable. TLS rollback precedes its critical-process wait and is not an equivalent checked reload lifecycle.

For eight eligible cases reaching registered cleanup with successful preceding stages, the insertion adds eight per-case raw reloads and one raw module reload before the existing checked reload — potentially ten reload invocations total, not an observed runtime count. Skips/early failures change the count.

**Smallest correction:** leave `_restore_config` as file-only restoration and preserve the existing one module-scoped checked reload. Closing as superseded or reworking the PR is a maintainer choice. Adding `-f` alone does not supply the checked lifecycle; blindly reloading after a failed file copy/compare is not the proposed remedy.
