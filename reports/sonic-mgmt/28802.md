## Summary
This repairs the command-presence test, not the implementation of `show techsupport`. The previously unconditional DNX2 DBAL names are moved into a seven-entry DNX2 list; mapped Q3D devices instead get five DNX3 names. Common DNX commands remain selected. Both families still use the existing single-/multi-ASIC formatter and `check_cmds` consumer.

The five new names match the actual alternate production branch in merged sonic-utilities#4326, pinned to merge `0a1bbc55a3996d7bd476e8fcbe030eac3ed4eae2`. Production intentionally folds host-route and LPM content into the newer FIB tables; omitting the old separate private-host names is not lost coverage against that producer. Parent-owned controls reproduce the old Q3D mismatch and its correction, while preserving legacy DNX2 expectations.

## Grounded nonblocking notes

### 1. Preserve a follow-up for the helper's unset-environment path
New dependency: `tests/show_techsupport/test_techsupport.py:532`; existing helper: `tests/common/plugins/conditional_mark/__init__.py:28–30,130–157`.

The actual default path expression resolves to `tests/ansible/group_vars/sonic/variables`, which is absent in the pinned tree. With `ANSIBLE_CONFIG` unset, the helper returns `None`, so even a listed Q3D SKU keeps DNX2 expectations. With the correctly configured ansible directory, the same real helper returns `q3d`.

The standard `tests/run_tests.sh:141` exports the correct directory, and the failing fallback produces the same expectation set as base. **This is an inherited incomplete-fix path, not an introduced Q3D or DNX2 regression.** A separate correction to the helper's default root, plus an unset/configured-path regression test, would make direct invocation less fragile. Until then, retain the launcher/environment requirement; do not imply the normal wrapper is broken.

### 2. Make the claimed Q3D validation auditable
The PR says master was tested and `test_techsupport.py` was rerun on Q3D. Credit that statement. Its test-result section and linked issue do not include the image version, exact HWSKU, selected `test_techsupport_commands` node/result or a log artifact. Those details would substantiate the image-dependent path. This is not an allegation that the author did not test.
