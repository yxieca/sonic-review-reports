## Summary

The added shutdown-before-reset scenario is useful. Scenario A also now checks link recovery when no LPMODE flap was needed, fixing a real coverage gap. Namespace-aware host commands and ordinary negative-reset-result handling are preserved.

The new Scenario B nonetheless uses a one-to-one reverse mapping where the fixture supports breakout siblings, unconditionally enables originally disabled interfaces, and has no exception-safe per-test restoration. These affect generic selected ports, not only CPO devices. The existing module-level configuration checker is a meaningful eventual recovery mechanism, but does not protect the following tests within the same module.

## Blocking issues

### 1. P2 — Restore interfaces even when Scenario B fails partway through

**Source:** `tests/platform_tests/api/test_sfp.py:999–1022,1035–1074`.

The new direct shutdowns are followed by inline startup only on the normal execution path. A client HTTP/JSON failure during reset, a later CPO-member shutdown error, or a startup exception exits without attempting the remaining restorations. There is no enclosing finally or requested function-scoped restoration fixture.

**Grounded evidence:** the coordinator executed the exact base/head `test_reset` methods, actual SFP RPC client and namespace-aware command wrappers with in-memory effects. A reset-response exception after successful shutdown leaves the head's general port admin-down; the same injection condition is not reached on base and leaves its port up. A CPO second-shutdown failure leaves the first member down; a CPO reset transport error leaves both selected members down. Successful and ordinary `False` reset controls still reach startup.

**Important qualification:** a vendor `reset()` exception normally becomes an HTTP-200 `res:null` response, and `expect()` is soft. Do not describe `False`/`None` alone as bypassing startup. Module-scoped `core_dump_and_config_check` can restore detected config drift at module teardown, so this is lost per-test isolation and avoidable delayed recovery—not proof of permanent DUT stranding.

**Requested correction:** register restoration before mutation, preserve the original failure, and attempt restoration for every changed member even if an earlier cleanup fails. Cover client failure and partial group shutdown/startup with regression tests.

### 2. P2 — Quiesce all logical siblings of the physical reset target

**Source:** `test_sfp.py:862–869`, callers at `994–1003,1036–1049,1067–1074`; setup reverse mapping at `66–81`.

`get_intf_name()` returns only the first interface sharing a physical index. Setup explicitly builds `index_physical_port_map[index]` as a list and deduplicates physical indices for testing. The new scenario therefore shuts down only one breakout subport before resetting the shared physical transceiver.

**Grounded evidence:** with `Ethernet0` and `Ethernet1` sharing index 0, the exact head method reaches Scenario B reset with admin states **down/up**, then completes successfully. The two-physical/four-logical CPO control has the same first-sibling omission. `interface_utils.py:247–279,389–428` establishes the mapping contract; the adjacent sfputil reset implementation records all logical siblings and disables them while resetting one representative.

**Impact:** on supported breakout wiring, the new test can pass without exercising its intended module-all-down reset precondition. Any actual hardware recovery failure is conditional and was not reproduced on a DUT.

**Requested correction:** use a complete one-to-many mapping for the intended reset unit, preserving the appropriate original state per logical member. Respect skip-list/connection scope explicitly rather than selecting an arbitrary first sibling. Add a multiple-logical-ports/one-physical-index ordering test.

### 3. P2 — Preserve initially admin-down interfaces on successful completion

**Source:** `test_sfp.py:992–1022,1035–1074`; selection at `50–81`; contrast the old admin-up filter at `443–465`.

Selection uses connected interfaces minus the transceiver skip list, not a universal admin-up filter. Scenario B always issues startup after reset. A populated, connected, non-skipped interface that was intentionally admin-down is therefore enabled even when the test succeeds.

**Grounded evidence:** an exact-source paired control starting with `Ethernet0=down` ends **down on base** and **up on head**, with no test-body failure. Existing same-file and neighboring sfputil code recognize original admin state; named topology skip exceptions are not a general guarantee that every selected interface starts up.

**Impact:** intended running config changes and later tests can inherit the altered state before module recovery. A finally that always performs startup would still leave this defect.

**Requested correction:** snapshot original admin states, restore initially down members to down, and verify the expected originally-up set. Alternatively explicitly restrict this scenario to suitable initially-up interfaces. Add the initially-down success-path regression independently of exceptional cleanup tests.

## Non-blocking notes

### Grounded nits and questions
- **Make the recovery oracle explicit** (`945–960,1078–1094`). The logged lists contain physical indices and only size the timeout; the callback receives no list and checks *current* DUT-wide admin-up ports. A synthetic successful-but-ineffective startup is omitted from that set and can pass. This is not an integer/type error or proof that the real CLI misreports success. A fixed expected logical/admin/oper set would strengthen the restoration checks.
- **Document and substantiate the CPO reset-domain contract** (`890–894,983–987`). Provide the actual type/index→OE mapping, group-wide reset semantics, sparse/filtered-member behavior and platform test evidence. Lack of that implementation in sonic-mgmt does **not** prove `(index-1)//8` is wrong; no off-by-one or wrong-hardware-group blocker is retained.
- **Validate the shutdown precondition and runtime** (`1002–1017,1046–1064`). Five seconds is a delay, not an observed down-state assertion. The exact 64-general-port control adds 640 seconds of programmed sleeps; this is a budget observation, not measured hardware walltime or a demonstrated timeout. Preserve any required hardware ordering.
- **Improve the PR context/evidence.** The title/body omit the material CPO grouping rationale, and testing identifies only version `202608`, without a hardware/topology/log receipt. Current green hosted checks are credited but are not physical-SFP/CPO qualification.

### Best-practice suggestions — not blocking
A small shared grouping/restoration helper may reduce duplicated scenario logic. Logged random representative selection provides useful failure context; optional seeded/parameterized coverage can help reproducibility, but forcing a single deterministic representative is not inherently better.
