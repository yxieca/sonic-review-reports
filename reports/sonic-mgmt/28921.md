## Summary
The new `DBChecker(...).verify_tunnel_route()` call at `tests/arp/test_arp_dualtor.py:552–555` waits on the selected interface’s existing cable-type-aware tunnel-route indicators after logical standby and before traffic. No packet retry or assertion weakening is added.

This is a useful convergence improvement, **not an unconditional exact-target or physical-forwarding guarantee**: the reused checker skips configured destinations without recognized neighbor entries. Its CLI “kernel” indicator is APPL_DB-derived; the ASIC indicator checks ASIC_DB route/tunnel-next-hop state. Final packet verification remains the functional oracle.

## Non-blocking notes
**Grounded limitations, not required repairs:**
- The checker is configured-server/port-wide rather than explicitly bound to the packet’s target address. Synthetic missing-neighbor controls demonstrate that it can accept without that destination’s route; no supported real transition producing this bypass was established. Base had no route barrier, and the packet assertion remains. Optional future target-specific hardening could make the intended guarantee stricter without globally removing the helper’s legitimate missing-neighbor policy.
- The inherited 30-second/10-second polling helper has no terminal poll. With instantaneous mocked commands it checks at0/10/20 seconds; readiness at30 is missed. Persistent query exceptions can instead end in an inherited `AttributeError` while formatting uninitialized mismatch data, still preventing packet send. Neither establishes an introduced functional blocker here.
- It also waits for other learned destinations on the same interface (other IP family, and SoC IPv4 for active-active). That can prevent the focused packet test from running when those routes are absent; those are still expected standby routes, so no unsupported “false failure” claim or mandatory AF narrowing is retained.

**Best-practice-only:** retaining target-ready, missing-route and absent-neighbor regression controls would be useful. No timeout tuning or generic helper refactor is required by this review. No default GitHub nit is recommended solely from these inherited limitations.
