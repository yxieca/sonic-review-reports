## Blocking issue

### P2 — Preserve the availability prerequisite before managed TLS provisioning

**Changed anchor:** [`tests/gnmi/test_gnmi_poll.py:17`](https://github.com/sonic-net/sonic-mgmt/blob/eafb857f06ae3445b7abfacef4f7b657d452320f/tests/gnmi/test_gnmi_poll.py#L17).  
**Existing discussion:** https://github.com/sonic-net/sonic-mgmt/pull/28601#discussion_r4518760414

Previously, `setup_gnmi_server` called `pytest_require(check_container_state(...))` before certificate creation or server provisioning (`tests/gnmi/conftest.py:89–93`). Replacing that dependency with `gnmi_tls` sends all five topology-`any` tests through `_gnmi_tls_flow`: checkpoint, certificate generation/copy and GNMI configuration precede `_restart_gnoi_server`, which raises an ordinary exception for the absent container (`tests/common/fixtures/grpc_fixtures.py:276–284,504–528,595–599`). Neither retained NTP/timestamp fixtures nor the inspected default conditional marks restore that capability check.

**Independently reproduced, with effects blocked:** exact extracted base setup returns a skip with no provisioning for an absent-container fake DUT; the head flow raises `The 'gnmi' container does not exist.` after recorded checkpoint/cert/config operations. Present-container controls yield successfully in both versions. The actual conditional-mark evaluator skips the 202412 control but does not skip the same POLL selection on 202605/master merely because gNMI is absent.

**Remedy:** add a selected-DUT support prerequisite guaranteed to run before managed TLS provisioning. Do not run both legacy and managed server-configuration fixtures together. This is an introduced caller-path regression despite the shared fixture implementation being unchanged. It is test setup/reporting correctness, not a demonstrated bad POLL packet or false-pass defect.
