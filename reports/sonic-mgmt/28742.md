## Decision

## Summary

The two-line change adds to the probe module the exact topology predicate already used by the `TestQosSai` class:

```python
topo_name not in constants['QOS_SAI_TOPO'] and asic_type not in ['mellanox','marvell-teralynx']
```

It skips all five probe methods on non-allowlisted topologies for non-exempt ASICs before their shared `QosSaiBase.dutQosConfig` setup. That fixture contains the Broadcom incomplete-buffer assertion reported in #28741. The assertion itself and traffic validation are not weakened. Existing issue/SKU/DNX exclusions remain effective; Mellanox/Marvell exemptions apply only to the new condition, not every other skip.

The source and actual selector controls support this topology-policy alignment. They do **not** establish that every newly suppressed configuration was failing, that legacy SAI replaces every probe observation, or that all lossy-topology failures are fixed.

`tests/common/plugins/conditional_mark/tests_mark_conditions.yaml:4617,4641–4642`

## Test-suppression scrutiny and known limits

- **Deliberate coverage reduction:** the rule covers XOFF, ingress drop, XON, egress drop and headroom pool, and applies beyond Broadcom. On excluded topologies, the legacy SAI class is also skipped—there is not replacement SAI execution there. No concrete supported, previously working lane newly lost contrary to the declared policy was established.
- **Egress probing is not an independently viable exception today:** despite its lossy focus, its signature and inherited autouse setup still require `dutQosConfig` and lossless profile fixtures. Keeping it on the reported failing configuration would require fixture changes, not merely omitting its skip.
- **Not a lossy detector:** `t0-isolated-d96u32s2` appears both in `QOS_SAI_TOPO` and the existing `lossyTopos` anchor. The new arm leaves that topology unchanged. No physical BUFFER_PG evidence establishes whether it is affected by #28741.
- **Not complete SAI/probe parity:** the pre-existing SAI `202412` release exclusion is not copied. Existing QoS-wide M* restrictions already apply to both suites. These are not introduced regressions.
- **Shared failure mechanism:** `qos_helpers.py:304–323` can return a partial buffer dictionary after a read/decode exception; the ordinary Broadcom branch asserts four entries at `qos_sai_base.py:2091–2101`. An empty successfully decoded PG dictionary is not the same as an omitted key. No live failure was reproduced.
