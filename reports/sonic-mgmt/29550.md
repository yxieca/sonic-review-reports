## Summary

The change correctly moves the complete NTP restart predicate inside the retry loop, preventing an already-active old process from causing immediate failure while the asynchronous restart is pending. Syslog add/duplicate/replace/remove checks now poll parsed configured targets; rollback polls equality with the original server set.

The substantive NTP restart and syslog presence/absence assertions remain. The final syslog checks observe `/etc/rsyslog.conf` through the pinned show command, not merely CONFIG_DB. No new supported false-pass or restoration regression survived source grounding.

## NTP acceptance and lifecycle

[Changed helper](https://github.com/sonic-net/sonic-mgmt/blob/e8a6af88b51c52d007b3979f3ba68c78538ac2d0/tests/generic_config_updater/test_ntp.py#L100-L112) now retries both conditions:

1. Selected service is active.
2. `ExecMainStartTimestamp` is greater than the pre-apply DUT timestamp.

BASE polled activity alone, then compared the timestamp once. For an active old service followed by a delayed restart, BASE could fail early; HEAD keeps observing until the restart condition is met.

The actual shared `wait_until` catches ordinary exceptions and pytest failures, logs them and retries. Timestamp read/conversion failures therefore do not escape immediately. Persistent failures still fail the outer assertion after the polling budget. The60-second/10-second values are a polling budget, not command preemption or a guaranteed number of observations.

Strict second-resolution `>` and malformed timestamp limitations are inherited parser choices, not new defects introduced by moving the comparison into polling. The source does not establish a newly supported fractional timestamp failure. File-content assertions follow the restart check; this does not establish NTP synchronization or every later service observation.

NTP checkpoint/rollback configuration comparison remains unchanged. It checks configuration restoration, not independent daemon-runtime readiness; that existing limitation is not promoted to a new cleanup blocker.

## Syslog acceptance, output and cleanup

[Changed helpers](https://github.com/sonic-net/sonic-mgmt/blob/e8a6af88b51c52d007b3979f3ba68c78538ac2d0/tests/generic_config_updater/test_syslog.py#L55-L143) distinguish a returned nonzero command status from a successful list. Both operation and rollback predicates reject None and continue polling.

The parser skips the one-column table header and removes each row’s brackets. All changed callers now supply bare server addresses, consistent with that representation. Exact list membership avoids accepting a neighboring address as a substring match.

The pinned sonic-utilities#5064 show handler reads `/etc/rsyslog.conf`, extracts `omfwd` targets, and emits bracketed single-column rows. File-read failures become a ClickException, not an empty successful table. A legitimate empty configuration does yield no rows. No source evidence establishes a malformed-successful-output failure in the supported path, so a hypothetical empty-output guard is not treated as a new blocker.

Operation checks remain expected/unexpected membership, not complete set equality. Only rollback compares complete sets, allowing ordering differences. Duplicate/extraneous rows are not newly claimed to be rejected. Negative patch tests still check operation failure, not every postfailure runtime invariant.

The finalization order remains rollback/reload, eventual server-set check, checkpoint deletion and Monit freshness handling. The existing helper can perform safe reload before reporting rollback failure. This update does not itself execute a new reload, modify cleanup ownership or prove global post-test health.
