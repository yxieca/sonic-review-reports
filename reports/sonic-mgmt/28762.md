## Blocking issues

### P2 — Keep exact-T2 generator and templates aligned for newly recognized NH-4210 fanouts

**Anchor:** `tests/common/helpers/pfc_storm.py:39`, with callers at `190–195`, `278–289`, `303–314`, and `439–454`.

For a newly recognized NH-4210 SKU on an **exact `t2`** DUT, deployment now replaces `pfc_gen_t2.py` with the XGS generator, but the earlier topology branch still selects `pfc_storm_sonic_t2.j2` and its stop counterpart. Those files contain CPU-generator options (`-t/-s/-n`) rather than the ASIC template’s chip/OS arguments.

Actual isolated Python selection methods reproduce the base/head pairing. The parent subsequently rendered the **complete pinned start templates with Jinja 3.1.6** and passed their extracted arguments into each generator's actual option-parser setup. Six controls cover both asymmetry branches: base exact-T2 CPU commands are accepted; head exact-T2 XGS commands reject `-t`; head LT2 XGS commands are accepted. The coordinator inspected the harness and receipts without rerunning tests. The head exact-T2 command exits during option parsing before storm generation, with output redirected to `/dev/null`; the all-port caller subsequently waits for a storm that this generator never starts.

**Required correction:** pair the selected executable with its matching start/stop templates on exact T2, or preserve the existing T2 CPU executable if XGS is intentionally unsupported there. A supported-topology exclusion must be explicit rather than inferred from the PR's LT2 motivation.

This mismatch already exists for O256 but is **newly triggered for real additional NH-4210 variants** such as P128-C1: base retains the T2 executable; head overwrites it with XGS. `PFCMultiStorm.set_storm_params` explicitly implements T2+SONiC, the all-port test declares topology `any`, and the inspected setup fixture does not exclude this fanout family. This establishes a supported-code-path regression without requiring evidence that a particular lab currently deploys this combination. Unobserved inventory limits incidence claims, not the proven conditional failure.

This does **not** demonstrate a failure on the advertised **`lt2`** topology: pinned topology classification/host wiring and executable/rendered controls distinguish `lt2`, `ft2`, and `t2`.
