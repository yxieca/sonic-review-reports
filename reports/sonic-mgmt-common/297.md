## R1 — Build independent commands separately

[CVL examples](https://github.com/sonic-net/sonic-mgmt-common/blob/06d2ac7a12fe89e96e6da16621a2ef89aa92e6fd/cvl/tests/BUILD.bazel#L3-L24) · [DB examples](https://github.com/sonic-net/sonic-mgmt-common/blob/06d2ac7a12fe89e96e6da16621a2ef89aa92e6fd/translib/db/test/BUILD.bazel#L3-L24) · [original Make recipe](https://github.com/sonic-net/sonic-mgmt-common/blob/06d2ac7a12fe89e96e6da16621a2ef89aa92e6fd/cvl/tests/Makefile#L21-L33).

`//cvl/tests:tests_lib` lists `cfg_validator.go`, `cv_acl.go`, `cv_edit_op.go` and `cv_vlan.go`, then embeds them in one `go_binary`. All four files declare `package main` and an unconditional `func main()`; two also repeat helper functions.

`//translib/db/test:test_lib` likewise combines `arloIssue29.go`, `testdb.go`, `testmap.go` and `testsubscribe.go`. Each declares `main`, and the latter pair repeats `handler`.

**Consequence:** Explicit builds of the new `//cvl/tests:tests` and `//translib/db/test:test` targets compile duplicate package-level declarations and cannot succeed. Original Make builds these as separate per-file executables. The Go files existed at BASE; the new regression is the Bazel source aggregation, not their independent-command design.

**Correction:** Define one `go_binary`/appropriate source library per standalone command, or omit unsupported manual programs from the graph. Compile the corrected public targets in selected validation. Do not merely hide them from a recursive build while still presenting an unbuildable public binary.

No Go compiler was run here. Complete declarations/source lists and standard package-level uniqueness establish this source error; inert inventory recorded four `main` definitions per target and the duplicate helpers. This is not a native Redis/ABI failure claim.

## R2 — Update or exclude the stale translib example

[New target](https://github.com/sonic-net/sonic-mgmt-common/blob/06d2ac7a12fe89e96e6da16621a2ef89aa92e6fd/translib/test/BUILD.bazel#L3-L19) · [actual caller](https://github.com/sonic-net/sonic-mgmt-common/blob/06d2ac7a12fe89e96e6da16621a2ef89aa92e6fd/translib/test/translibtest.go) · [current API](https://github.com/sonic-net/sonic-mgmt-common/blob/06d2ac7a12fe89e96e6da16621a2ef89aa92e6fd/translib/subscribe.go#L37-L68).

`//translib/test:test` newly compiles `translibtest.go` against `//translib`. Its `main` calls `IsSubscribeSupported(paths)` with `[]string`, `Subscribe(paths,q,stop)` with three positional arguments, and reads `SubscribeResponse.Payload`.

Current functions require `IsSubscribeRequest` and one `SubscribeRequest`. `SubscribeResponse` exposes `Update`, `Delete`, `Path`, `Timestamp`, `SyncComplete` and `IsTerminated`, not `Payload`.

**Consequence:** This public target fails type checking independently of the runtime operation flag; Go checks the incompatible branches whether or not `-o subscribe` is selected. The API/caller mismatch is old source, but its newly declared Bazel compilation route is introduced here. Existing production-library CI does not build this target.

**Correction:** Migrate the example to current request/response types and validate its compilation, or keep the unsupported example outside the new target graph. No subscription API change, runtime subscription failure or compiler execution is claimed by this review.
