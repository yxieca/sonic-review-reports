## Summary

The router completion hook records final method/status/latency and the matched route pattern, with separate connection-level unauthenticated handling. Approved body fields are extracted deliberately; addresses/session identifiers are keyed pseudonyms. The nonblocking authpriv datagram sink counts failed sends and emits a later gap. Leak/host events use explicit severity independently of request/read log level. CONFIG_DB changes are republished through a read-only D-Bus property so bmcweb need not access Redis.

These are useful boundaries. Their source coverage is not proof of a complete audit history: reads and unauthenticated refusals are sampled, accepted telemetry is aggregated, upgrades follow a separate route, and actual transport delivery is best-effort. The current code additionally discards a promised suppressed-read count and omits a concrete early401 response. Native test success remains unverified; the NUL test is correct in the authoritative Git blob.

## R1 — withdrawn: source-retrieval artifact, not a test defect

The initial raw-text API adapter transformed a literal Unicode NUL escape into a visible control-character representation. **The authoritative Git blob is correct.** Its base64 content matches immutable blob `c93ddff9a507567dbbecf0538444ddd475fdc11f` and expects the same Unicode U+0000 escape the encoder produces.

A Git-blob integrity audit checked170 staged target/base/external files and found only this one transformed source. It was repaired from base64 and verified against the immutable blob hash. Other source findings and pins were unaffected. No native test ran, and there is no evidence this authored assertion fails. R1 is explicitly withdrawn; historical erroneous-input receipts are retained, not counted as validation.

## R2 — suppressed-read accounting is overwritten before emission

In [recordCompleted](https://github.com/sonic-net/sonic-redfish/blob/8e26302ff30e0ee986add3bb2dae0a0ce28d394b/redfish-audit/bmcweb/redfish_audit_hook.hpp#L548-L627), a read admitted after rate limiting calls `takeSuppressed`, resets the limiter's count, and puts it in `record.detail`. Later the ordinary non-session/non-denied branch unconditionally assigns `record.detail = buildDetail(...)`.

For a normal Systems GET, `buildDetail` returns an empty string; for an account/subscription GET it may replace the count with route identifiers. Either way, the promised `detail.suppressed` does not survive. Suppressed reads never reach Sink, so its sequence number does not reveal those omissions either.

**Condition/consequence:** exceed the50-per-second DEBUG read limit, then admit a later read. Consumers cannot tell how many reads were left out despite the documented next-record accounting. The standalone limiter test correctly counts/reset values but never reaches the later overwrite.

**Base/evidence:** the limiter/hook path is new. Full source/caller inspection and an explicitly source-derived assignment-order control confirm overwrite/reset; no native hook or syslog output was executed. Merge the suppression value into the final detail after route-detail construction, and add a hook-to-serialized-record regression rather than testing the limiter alone.

## R3 — an early HTTP/1 authentication refusal bypasses auditing

The exact pinned [HTTP/1 connection](https://github.com/openbmc/bmcweb/blob/6926d43047446a1f08d4b157d48a30221ae8f87e/http/http_connection.hpp#L543-L660) authenticates after headers, then checks content length before constructing/routing the completed request. An unauthenticated request with declared content length greater than4096 but below the global body limit receives401 in `handleContentLengthError`, followed by direct `doWrite` and return, when not using the100-continue branch.

[Patch0012](https://github.com/sonic-net/sonic-redfish/blob/8e26302ff30e0ee986add3bb2dae0a0ce28d394b/patches/0012-Record-an-audit-trail-of-Redfish-requests.patch) adds unauthenticated auditing inside later `handle` and ordinary auditing in Router::handle. Neither executes for this early return. Earlier lifecycle patch0010 does not redirect that size-error boundary.

**Consequence:** a genuine401 response has no denied audit record or audit-suppression accounting. This is an audit omission, not an authentication bypass or permission to log rejected body/header content.

**Base/evidence:** the early response existed before; the incomplete new coverage claim is introduced by the audit feature. Ordinary credential failures and HTTP/2 denials are separately covered, so this is the specific HTTP/1 size range, not every parser error. Exact source predicate/control inspection shows the4097-byte logged-out branch returns401 before routing; no request or BMC connection was sent.

Instrument the early401 boundary with already parsed method and a constant unauthenticated marker, preserving raw-target/header redaction. Add a bounded owner-run HTTP/1 case for this size range and assert exactly one record, not duplicate connection/router records.

## Q1 — inherited HTTP/2 DEBUG credentials remain outside the redacted audit stream

The pinned [HTTP/2 header callback](https://github.com/openbmc/bmcweb/blob/6926d43047446a1f08d4b157d48a30221ae8f87e/http/http2_connection.hpp#L457-L467) logs header name **and value** at DEBUG before authentication. Normal Authorization, X-Auth-Token and Cookie headers therefore reach ordinary bmcweb logging when DEBUG is enabled. HTTP/2 is enabled by default in the pinned Meson options; this patch does not remove that header-value logger.

The new CONFIG_DB-driven level path raises bmcweb's general log level to DEBUG as well as enabling read-audit records. The statement is inherited, and upstream already offered a D-Bus SetLogLevel route, so this is not a wholly new credential-disclosure primitive. Nevertheless, sanitizing authentication.hpp and audit JSON cannot remove the earlier ordinary-log copy. Do not advertise the new DEBUG operation as universally credential-safe without closing or explicitly constraining this sink.

Remove arbitrary header values or apply a strict sensitive-header redaction at the callback; alternatively decouple read auditing from general DEBUG until safe. The regular HTTP/1 INFO logger also retains dynamic URL paths even though audit `uri` is a route pattern; audit-field promises are not all-service-log promises. No actual credential, endpoint or log stream was tested, and no private data was read for this review.

## Q2 — failed account creation and proposed username policy

The account POST annotation allows a syntax-checked UserName and RoleId without requiring successful account creation. The exact account handler can reject the role before CreateUser, while the audit hook still records the proposed UserName. Unlike the successful-session-only username branch, this could retain a password-like token accidentally entered in that field.

An authorized caller is required, account-name auditing is intentional, and the syntax filter prevents forged JSON/log lines. Those constraints do not determine whether failed attempted account names are part of the accepted audit policy. A stronger privacy severity was proposed by the SME; coordinator synthesis retains an explicit policy question rather than claiming an authorization bypass or that every identifier-shaped body value is secret.

Prefer successful/accepted target identity, or explicitly document the intended failed-account input exception and add the corresponding privacy test. Keep actor identity/method/route/result without copying a failed proposal if the policy forbids it.

## Nonblocking completeness and lifecycle notes

- Accepted SubmitTelemetry requests are counted and aggregated, not recorded one-per-request; rejected calls remain ordinary records. Summary flush occurs on a later completed request, not an independent timer. Unauthenticated denials are sampled20/sec, reads50/sec. These documented throughput choices are not automatically defects, but “every request/refusal” needs that exception and suppressed accounting must actually survive R2.
- WebSocket/SSE upgrade requests use a separate handler before ordinary routing. Post-upgrade traffic is not an HTTP mutation covered by this model; initial DEBUG read/denial completeness should be documented and separately verified.
- HTTP/2 may omit the client pseudonym where upstream leaves Request.ipAddress unspecified; this is missing attribution, not leakage of the raw address.
- A non-cancellation `async_wait` error can leave ConfigKeyWatcher without a rearmed wait; the common readable/Redis-failure path disconnects and retries. Optional hardening should retry non-aborted wait errors, not restart canceled/stopped watches.
- Allowed token syntax is not a secrecy oracle. PATCH changed-key names and approved alert/account fields intentionally disclose limited body-derived metadata. The privacy claim should describe those explicit exceptions rather than asserting no request-body data whatsoever.
- The PR description still names patch0011 whereas current series uses0012; this is a documentation nit. Runtime owner matching, initial/refetched log levels and service restart handling are otherwise source-supported.

## Favorable architecture and source-supported boundaries

The audit hook uses route patterns and unauthenticated placeholders, not audit raw targets; failed session login avoids proposed usernames; addresses/session identifiers are keyed pseudonyms. The encoder escapes control characters/non-ASCII rather than accepting log forging. Commands and refusals remain independent of read-level filtering.

The sink uses nonblocking datagram/CLOEXEC and nonblocking sends at authpriv severity. Drops advance counters; a later successful send reports a gap. The socket mechanism is nonblocking, but parsing, formatting/allocation and first-use random initialization remain synchronous; no measured request-latency guarantee is established by source alone.

The Docker builder separately preinstalls sdbusplus `a74f63b1903c8b00d9c134164eaa4ac8e925d0f5`, distinct from the wrapped `54d3...` source, and dependency resolution can prefer it. No native compiler failure is diagnosed, and compatibility of every installed-library path is not certified. The completion wrapper moves the next callback to stack before invoking a connection handler that can replace/destroy captures. Exact Response set/release/end ownership and prior lifecycle patches were inspected, not assumed. Event audit happens before event dispatch even without subscriptions. Logging D-Bus property has the bridge owner's sender match; invalid CONFIG values are not echoed, unreadable DB retains the current level and retries.

Makefile copies both audit headers before applying patch0012 and adds their unit include path. `make build` now invokes existing clean logic to obtain a pristine source tree; that destructive build/developer side effect is documented here but was not executed. No credential-based runtime API, new service mutation or external transmission was performed by this review.
