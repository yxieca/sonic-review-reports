## Summary and actual source effect

The entire delta is one additional set member, `switch-platform-init.service`, in [aspeed_bmc_filter_services.py](https://github.com/sonic-net/sonic-buildimage/blob/7d9e0caac5be00833b484fa69e41d1873a83f89a/files/build_scripts/aspeed_bmc_filter_services.py#L22-L35). The existing evaluator subtracts excluded names from the generated service list, preserves/adds required BMC services, removes target.wants links and creates an `/etc/systemd/system/<unit>` symlink to `/dev/null` when appropriate.

The actual [image-extension caller](https://github.com/sonic-net/sonic-buildimage/blob/7d9e0caac5be00833b484fa69e41d1873a83f89a/files/build_templates/sonic_debian_extension.j2#L1446-L1475) invokes the filter only for `CONFIGURED_PLATFORM == aspeed`, at the end after service registration. It supplies both the generated list and staged filesystem root, then replaces the list with the filtered output. This is build-time image-role selection, not a global runtime mask based merely on CPU architecture. Other configured platforms do not enter that branch.

## Reached initializer and preserved BMC roles

The absence of a switch metadata publisher on a BMC is an intentional role exclusion. No actual supported BMC caller was found that requires this switch-specific readiness output. A generic guess that every system must publish SWITCH_INIT_DONE is not used as a blocker; source role, actual selected producer and platform caller boundaries were checked.
