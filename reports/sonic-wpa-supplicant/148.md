## Summary

This is a narrowly scoped correction to the MACSEC control reply's byte-count contract. The old formatter returned the space remaining at the beginning of a truncated line, rather than the bytes stored across the reply. The control dispatcher and transports use the returned number directly as the send length.

The new implementation accumulates the established `wpa_scnprintf()` helper's stored-byte count, excludes the terminating NUL, and stops association traversal when full. Default/full-fit status text and the public signature remain unchanged. The new test links the production formatter and helper, rather than copied implementations, and covers capacities zero through 199 around a 197-byte TX/RX fixture.

No introduced memory-safety, output-length, authorization, supported Linux build-design or MACsec state-change defect survived independent grounding.

## Why the correction is sound

### Stored bytes, not remaining space

[Changed complete formatter](https://github.com/sonic-net/sonic-wpa-supplicant/blob/5c45e5df3363d59a45c5d43333d8f1af254e58e0/src/pae/ieee802_1x_kay.c#L5001-L5078) · [actual helper contract](https://github.com/sonic-net/sonic-wpa-supplicant/blob/5c45e5df3363d59a45c5d43333d8f1af254e58e0/src/utils/common.c#L263-L291) · [BASE implementation](https://github.com/sonic-net/sonic-wpa-supplicant/blob/3b12459b9d6c954ed74519c793f2b65f67361ea1/src/pae/ieee802_1x_kay.c#L5011-L5090).

`wpa_scnprintf` returns actual stored non-NUL bytes, capped at `size-1`, or zero for a negative formatting result/zero size. For a valid KaY and positive capacity, each append maintains `0 <= len <= buflen-1`. The next call therefore receives at least one byte of remaining capacity; `buf+len` stays inside the supplied buffer. At saturation, a size-one append contributes zero and retains the terminator. Association-loop guards return the already accumulated length.

Capacity zero returns without touching the buffer. Capacity one stores only NUL and returns zero. Fitting replies retain their existing content and non-NUL length; truncated replies are the permitted byte prefix. The actual per-interface control buffer is 4096 bytes, so the helper's integer return and final `size_t`→`int` conversion are bounded well below `INT_MAX`. Hypothetical enormous external buffers do not demonstrate a new defect in the inspected callers.

### The real caller consumes the exact count

[MACSEC dispatcher](https://github.com/sonic-net/sonic-wpa-supplicant/blob/5c45e5df3363d59a45c5d43333d8f1af254e58e0/wpa_supplicant/ctrl_iface.c#L10507-L10591) · [final response length](https://github.com/sonic-net/sonic-wpa-supplicant/blob/5c45e5df3363d59a45c5d43333d8f1af254e58e0/wpa_supplicant/ctrl_iface.c#L11420-L11432) · [Unix send](https://github.com/sonic-net/sonic-wpa-supplicant/blob/5c45e5df3363d59a45c5d43333d8f1af254e58e0/wpa_supplicant/ctrl_iface_unix.c#L177-L205) · [CLI consumer](https://github.com/sonic-net/sonic-wpa-supplicant/blob/5c45e5df3363d59a45c5d43333d8f1af254e58e0/wpa_supplicant/wpa_cli.c#L228-L263).

The dispatcher allocates 4096 bytes, obtains `reply_len` from the formatter, and returns it through `resp_len`. Unix/UDP/named-pipe transports use that number; the client receives a byte count and adds its own terminator. This establishes the concrete user-visible consequence of the old count error and the compatibility of the new return value.

The formatter reads the existing cipher/SCI/association state. It does not install keys, invoke the driver, alter associations, or change control access policy. `sci_txt` uses an existing fixed scratch buffer. The change does not introduce a new authentication endpoint or expose CAK/CKN material. Existing NULL-KaY, verbose-command interpretation and sibling formatter behavior were not misclassified as newly introduced defects.

### The authored regression reaches production code

[Test source](https://github.com/sonic-net/sonic-wpa-supplicant/blob/5c45e5df3363d59a45c5d43333d8f1af254e58e0/tests/test-macsec_status.c#L1-L56) · [production-link rule](https://github.com/sonic-net/sonic-wpa-supplicant/blob/5c45e5df3363d59a45c5d43333d8f1af254e58e0/tests/Makefile#L54-L58).

The expected text contains 197 bytes; including its NUL, the expected array has 198 bytes. `reply[sizeof(expected)+2]` allocates 200 bytes, and the loop covers all 200 capacities from zero through 199. Each case checks returned length, prefix bytes, terminator and the first byte beyond the requested capacity. Its maximum sentinel index is 199, inside the allocation.

The Makefile links `test-macsec_status.c`, production `ieee802_1x_kay.c` and production `common.c`, with `CONFIG_CTRL_IFACE` and section garbage collection. This removes unrelated protocol dependencies without substituting the formatter. The declared GNU-style compiler/linker flags fit the workflow's Ubuntu environment; native macOS/MSVC support was not asserted.

These are authored test properties, not 200 tests executed by this review. The single-TX/single-RX fixture covers formatting boundaries but not repeated association-loop iterations; a multi-element fixture is an optional strengthening, not an acceptance requirement.
