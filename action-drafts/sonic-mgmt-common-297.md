## Questions

Could these newly exposed public command targets be corrected before accepting the build graph?

Must-fix public-target compilation — keep standalone programs separate. cvl/tests/BUILD.bazel::tests_lib selects cfg_validator.go,cv_acl.go,cv_edit_op.go,cv_vlan.go, each with unconditional package main/func main(), then embeds all four in one binary. translib/db/test/BUILD.bazel::test_lib does the same for arloIssue29.go,testdb.go,testmap.go,testsubscribe.go (also duplicate handler). These newly declared public targets cannot compile duplicate package-level functions. BASE Make builds per-file executables; the old individual programs are not defective merely for each having main. Please create one command/source group per program or omit unsupported examples, and validate compilation of the public targets. This is a source-declaration failure, not an executed Go test or a claim that selected production CI failed.

Must-fix public-example API — migrate or exclude the stale subscription caller. translib/test/BUILD.bazel::test newly compiles translibtest.go against current //translib. The complete main calls IsSubscribeSupported([]string), Subscribe(paths,q,stop), and SubscribeResponse.Payload, while translib/subscribe.go requires IsSubscribeRequest, one SubscribeRequest, and Update/Delete fields with no Payload. Go type-checks those branches even when another runtime operation is chosen. Update to the current request/response API and validate this target, or leave the unsupported example outside the new graph. The API mismatch is old source; exposing it as a newly buildable public target is introduced here, not a new subscription API change.

Nonblocking cleanup: cvl/cvl_test.go::clearDb calls os.Exit on Redis Keys/Del error, bypassing its defer and TestMain’s cleanup/possible legacy self-started Redis stop. Return the error and attempt owner cleanup before final exit; the Bazel parent still owns its private Redis. Existing consumer version/glog/registry and libyang-parity threads are already raised; respond there rather than duplicating them. The reported libyang UAF trigger was not shown reachable through CVL’s inspected parser flags, so no runtime crash claim is added.
