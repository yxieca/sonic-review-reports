## Request changes with comments

The source review supports the REST/CLI producer and owner runtime/debug separation, but the retained legacy cleanup must preserve the new permanent OpenAPI Bazel package.

**Preserve the new OpenAPI Bazel package during legacy cleanup.** The PR adds [rest/openapi/BUILD.bazel](https://github.com/sonic-net/sonic-mgmt-framework/blob/b86870c041c672e1b3cc131d4718cc251c7322c5/rest/openapi/BUILD.bazel#L1), and [the new models library](https://github.com/sonic-net/sonic-mgmt-framework/blob/b86870c041c672e1b3cc131d4718cc251c7322c5/models/BUILD.bazel#L1-L37) resolves `//rest/openapi:routes.go`. However, the unchanged [models/openapi_codegen.mk clean target](https://github.com/sonic-net/sonic-mgmt-framework/blob/b86870c041c672e1b3cc131d4718cc251c7322c5/models/openapi_codegen.mk#L1) deletes every regular file in that directory except `routes.go`. [Root models-clean/rest-clean/clean](https://github.com/sonic-net/sonic-mgmt-framework/blob/b86870c041c672e1b3cc131d4718cc251c7322c5/Makefile#L82-L98) reaches that recipe. Running retained legacy cleanup therefore deletes the new tracked BUILD file, leaving a source deletion and breaking subsequent Bazel label resolution until it is restored. Please exclude the permanent BUILD file or restrict deletion to known generated Go files, and add a cleanup/coexistence regression. This is a new-path integration defect: the cleanup predicate is inherited, but the additional permanent package file is new. The source predicate was checked without executing Make, find, deletion or Bazel.

**Nonblocking: make the installed CLI syntax probe's no-service boundary explicit.** [CLI/bazel/installed_probe.py](https://github.com/sonic-net/sonic-mgmt-framework/blob/b86870c041c672e1b3cc131d4718cc251c7322c5/CLI/bazel/installed_probe.py#L13-L53) builds a private HOME and loader/library environment, but does not set `CLISH_NOAUTH`. The owned [nos_extn_init](https://github.com/sonic-net/sonic-mgmt-framework/blob/b86870c041c672e1b3cc131d4718cc251c7322c5/CLI/klish/patches/klish-2.1.4/plugins/clish/nos_extn.c#L109-L127) enables the authentication bootstrap when that variable is absent; [the REST client](https://github.com/sonic-net/sonic-mgmt-framework/blob/b86870c041c672e1b3cc131d4718cc251c7322c5/CLI/klish/patches/klish-2.1.4/plugins/clish/rest_cl.cpp#L190-L255) defaults to `http://localhost` through `/var/run/rest-local.sock` and fetches `/authenticate`. A private extraction directory does not isolate an absolute host socket, and `-k` command checking is not itself a guard around plugin initialization. Could command-tree-only checks set `CLISH_NOAUTH=1`, or explicitly provide a private authentication fixture and documented execution boundary? This is a new test-isolation concern, not a new production TLS/authentication bug. Exact source-archive/compiled startup qualification and live socket behavior were not probed; the recommendation is deliberately nonblocking with those bounds.

**Nonblocking: update the selected-dependency prose.** [tools/bazel/README.md's Review dependencies](https://github.com/sonic-net/sonic-mgmt-framework/blob/b86870c041c672e1b3cc131d4718cc251c7322c5/tools/bazel/README.md#L24-L36) still names Management Common `1.0.1-05f83d…` and Infra `0.0.28`; [CLI/bazel/README.md](https://github.com/sonic-net/sonic-mgmt-framework/blob/b86870c041c672e1b3cc131d4718cc251c7322c5/CLI/bazel/README.md#L1-L85) also refers to an older selected Infra lock. [MODULE.bazel](https://github.com/sonic-net/sonic-mgmt-framework/blob/b86870c041c672e1b3cc131d4718cc251c7322c5/MODULE.bazel#L9-L15) actually selects Common `1.0.2-68bfd75…` and Infra `0.0.45-77ef625…`. Please update the durable guidance or mark those references historical, so readers inspect the correct source/tool/package contracts. Build labels use the actual module declarations, limiting this to documentation accuracy.
