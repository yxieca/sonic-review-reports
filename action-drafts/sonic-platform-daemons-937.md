R1 — bank-aware VDM source reads remain required. In sonic-xcvrd/xcvrd/cpo/cpo_dom_mgr.py::collect_and_publish_data and the inherited VDM publisher/threshold path, each bank-bound port reaches a shared CmisVdmApi raw reader that uses page*128+128 without the bank stride. XcvrEeprom forwards that offset unchanged, and the inspected banked platform transport decodes bank0. A nonzero-bank port can therefore publish bank0 values/thresholds or miss a bank-only alarm under this combination. Make descriptors, values, thresholds and flags bank-aware and select a compatible reader before enabling the CPO path; cover distinct bank inputs and bank0 controls. Existing R1 is already discussed; respond there rather than reposting. Merely using the correct API object or adding common790 does not prove this raw-reader issue is fixed.

N2 — an older compatible API lacking this optional method produces a contained AttributeError error log at applicable READY transitions. Detect method absence like unsupported while preserving implemented-hook failures; this is diagnostic compatibility, not a demonstrated link/daemon failure.

Q1 — shared-OE metadata ownership/deduplication is separate from eventual retry; per-bank READY calls can repeat module-shared serial-number work. Preserve readiness/serialization and required fanout if consolidating snapshots. Q2 — dom/utilities/vdm/utils.py and the CPO threshold path expect SFP-style port wrappers, whereas CpoBase exposes an API-oriented get_xcvr_api boundary. An API-only port without the extra wrappers can raise AttributeError, but the inspected NVIDIA port supplies them. Prefer CPO VDM access through the API or define a consistent safe capability contract; do not assert all platforms fail, or treat swallowing one support error as full flags/threshold functionality. The existing author response favors a single API override location.
